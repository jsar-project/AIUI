# Camera 页面扫码页设计

## 背景

当前 `samples/scanner/pages/camera/index.ink` 已具备扫码主链路，但页面仍保留较多调试和过程性展示，不够适合眼镜端日常使用。
目标是进一步将该页面收敛成一个极简扫码页：用户进入页面后只看到标题和提示，点击眼镜硬件按键后执行拍照和解码，在解码过程中显示状态，完成后只展示图片和扫码结果。

## 目标

- 将当前页面收敛成极简扫码页
- 使用眼镜硬件按键事件，通过 `onKeyDown` 监听 `Enter` 触发扫码
- 扫码流程采用“拍照 -> decode -> 识别”
- 解码阶段向用户显示明确的进行中状态
- 扫码完成后同时展示照片预览和识别结果
- 再次按硬件按键时直接开始下一次扫码，并覆盖旧图和旧结果

## 非目标

- 不实现实时连续扫码
- 不实现识别结果自动跳转、自动打开链接或自动路由
- 不保留独立的拍照演示按钮或屏幕点击触发入口
- 不保留调试信息卡片和底层格式诊断文案
- 不修改现有 `BarcodeDetector` 或相机 API 文档约定

## 选定方案

采用“极简扫码页 + 硬件按键触发”方案：

- 页面不保留按钮、调试卡片和冗长说明
- 页面默认展示标题、提示文案和相机预览
- 用户点击眼镜硬件按键后触发一次完整的“拍照 -> decode -> 识别 -> 展示结果”流程
- 解码期间页面显示 `Decoding...`
- 再次点击眼镜硬件按键时直接覆盖旧图和旧结果

选择这个方案的原因：

- 页面定位更清晰，直接就是扫码页
- 与眼镜硬件交互更贴合
- 页面信息密度更低，更适合眼镜端
- 重复扫码行为简单直接，适合 sample

## 页面结构

页面保持极简三段式结构：

1. 顶部标题和提示区
2. 中部相机预览区
3. 底部结果展示区

具体调整如下：

- 顶部只保留一个标题，例如 `Barcode Scanner`
- 标题下只保留一行提示，例如 `Press the glasses button to scan`
- 相机预览继续保留，便于取景
- 页面只保留一行状态文案，用于显示 `Ready`、`Decoding...`、`Done` 或错误
- 扫码完成后展示结果文案和最新图片
- 不展示独立的调试块、原始元数据或复杂列表容器

## 数据模型

页面 `data` 仅保留完成交互所需的字段：

- `isScanning`: 布尔值，用于阻止重入
- `status`: 字符串，用于控制简化后的状态文案
- `errorMessage`: 字符串，用于显示失败信息
- `photoUrl`: 字符串，用于展示最新图片
- `scanResultText`: 字符串，用于展示识别结果

状态值收敛为：

- `READY`
- `DECODING`
- `DONE`
- `ERROR`

## 方法设计

新增：

- 一个内部公共拍照方法，用于统一处理相机上下文初始化、拍照、预览地址生成和照片对象返回
- `scanBarcode()`
- `onKeyDown(event)`

职责划分：

- `onKeyDown(event)` 负责响应眼镜硬件按键中的 `Enter`
- `scanBarcode()` 负责整条“拍照 -> decode -> 识别 -> 更新 UI”链路
- 公共拍照方法只负责拍照和生成可展示图片

页面生命周期要求：

- 页面显示时注册按键监听
- 页面隐藏或销毁时移除按键监听，避免重复注册

## 交互流程

### 页面初始状态

- `status = 'READY'`
- `isScanning = false`
- 页面显示标题、提示和相机预览

### `onKeyDown`

1. 监听页面硬件按键事件
2. 当按键不是 `Enter` 时忽略
3. 当 `isScanning = true` 时忽略
4. 当按键是 `Enter` 且当前不在处理中时，触发 `scanBarcode()`

### `scanBarcode()`

1. 设置 `status = 'DECODING'`
2. 设置 `isScanning = true`
3. 清空旧的 `errorMessage`
4. 清空旧的结果文案
5. 调用公共拍照方法并更新 `photoUrl`
6. 执行 WebP 解码和条码识别
7. 根据返回结果更新页面
9. 在结束阶段统一恢复 `isScanning = false`

结果分支：

- 有识别结果：
  - `status = 'DONE'`
  - 保留 `photoUrl`
  - 写入简洁结果文本，优先展示第一条 `rawValue`
- 无识别结果：
  - `status = 'DONE'`
  - 保留 `photoUrl`
  - `scanResultText = 'No barcode detected.'`
- 发生异常：
  - `status = 'ERROR'`
  - 写入 `errorMessage`
  - 若已得到可预览照片，则继续保留

重复扫码规则：

- 再次按 `Enter` 时，直接开始新的扫码流程
- 新图片覆盖旧图片
- 新结果覆盖旧结果

## 结果展示

页面完成扫码后展示两个核心内容：

- 一行结果文案
- 一张最新图片预览

结果文案规则：

- 有结果时优先展示第一条 `rawValue`
- 如有必要，可在同一行补充 `format`
- 无结果时显示 `No barcode detected.`
- 出错时不展示旧调试信息，只展示面向用户的错误文案

第一版不做以下增强：

- 复制按钮
- 自动跳转
- 多结果列表
- 对 URL、Wi-Fi、文本等不同内容做类型化渲染

## 错误处理

统一面向页面显示的错误信息：

- 相机不可用：`Camera is unavailable.`
- 拍照失败：`Failed to capture photo.`
- 无法完成扫码：`Failed to scan barcode.`
- 无法完成解码：`Failed to decode photo.`

无结果不是错误：

- 使用 `DONE` 状态
- 不写入 `errorMessage`
- 通过 `scanResultText` 告知用户没有识别到条码

重入保护规则：

- 当一次扫码尚未完成时，后续 `Enter` 按键不触发新流程
- 这样可以避免并发拍照或并发识别

## 实现前置校验

当前已确认的拍照结果字段只有：

- `data`
- `mimeType`

当前已确认的 `BarcodeDetector.detect()` 输入要求包含：

- `data`
- `width`
- `height`

由于相机当前返回的是编码后的图片数据，因此实现时必须在页面内部先完成 WebP 解码，再将像素数据转换为 `BarcodeDetector.detect()` 可接受的灰度输入。

明确约束如下：

- 如果解码成功，则直接完成扫码实现
- 如果解码失败，不应伪造尺寸或像素数据
- 如果解码失败，页面应显示明确的失败文案，并保留拍照预览

## 验证点

- 页面打开后能正常显示标题、提示和相机预览
- 点击眼镜硬件按键时能触发一次扫码
- 解码期间页面能显示 `Decoding...`
- 连续快速点击按键不会造成并发扫码
- 识别成功时，页面正确显示结果文案与最新图片
- 无识别结果时，显示 `No barcode detected.`
- 再次点击按键时，新结果和新图片覆盖旧内容
- 解码或扫码失败后再次尝试，页面仍可恢复正常
- 页面离开后不会残留按键监听
